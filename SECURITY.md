# Security policy

## Scope

This policy covers security and privacy concerns related to this
repository, its published files, release-verification tooling, and
repository automation.

Scientific disagreement, numerical discrepancies, and reproduction
questions are not security vulnerabilities. Report those through a
GitHub issue using the appropriate template.

## Report privately

Report the following matters privately:

- exposed credentials, tokens, private keys, or signed URLs;
- private reviewer links;
- identifiable or potentially re-identifiable participant data;
- controlled-access or restricted source data;
- an access-control bypass;
- malicious modification of release or checksum records;
- a vulnerability in repository automation;
- a disclosure that should not appear in a public issue.

Send the report to:

`contact@helena.bio`

Use the subject:

    Security report: endometrial-developmental-regulons

## Include in the report

Where available, include:

- a concise description of the concern;
- the affected path, commit, release, or workflow;
- steps needed to reproduce or verify it;
- the possible privacy or security impact;
- whether any sensitive material is already public;
- a safe way to contact you.

Do not attach restricted data, credentials, or identifiable participant
information until a secure exchange method has been agreed.

## Response

Helena Bioinformatics will acknowledge the report, assess its scope, and
coordinate remediation and disclosure where appropriate.

Public disclosure should wait until the issue has been investigated and
affected credentials, files, or automation have been secured.

## Supported versions

Security corrections apply to the current default branch and, once
published, the latest versioned release.

Older repository commits remain part of Git history but are not maintained
as independently supported software versions.

## Data-access boundary

This repository does not grant access to controlled or restricted upstream
data. Source access remains governed by the responsible repositories and
their terms.
