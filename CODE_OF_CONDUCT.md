# Code of conduct

## Purpose

This repository supports scientific inspection, correction, and reproduction
of the endometrial developmental-regulon study.

Discussion may include disagreement about methods, code, data provenance,
statistics, interpretation, or reproducibility. Such disagreement is
welcome when it is specific, evidence-based, and directed at the work
rather than the person.

## Expected conduct

Participants are expected to:

- address the scientific claim, code path, input, output, or provenance
  record at issue;
- distinguish observed facts from interpretation;
- identify the repository commit and relevant analysis package when
  reporting a discrepancy;
- provide reproducible examples where reasonably possible;
- state deviations from the frozen protocol;
- correct mistakes openly;
- respect privacy, access, licensing, and data-redistribution rules;
- communicate professionally and in good faith;
- allow maintainers and contributors reasonable time to investigate.

Strong criticism of a method, result, or interpretation is permitted. It
should explain what is wrong, where the problem occurs, what evidence
supports the concern, and what consequence follows.

## Scientific integrity

Participants must not:

- fabricate, alter, suppress, or selectively report analytical results;
- misrepresent a post-hoc analysis as prespecified;
- describe directional concordance as confirmatory replication when the
  frozen evidential rules do not support that claim;
- describe an association as causal evidence without an appropriate design;
- omit a known deviation from the documented inputs or protocol;
- alter checksums or manifests to conceal an unexplained file change;
- present verification of published files as a full analysis rerun;
- use the repository to make unsupported clinical or therapeutic claims.

Corrections should preserve the prior state in Git history and explain the
effect on numerical results, categories, verdicts, figures, and manuscript
wording.

## Unacceptable behaviour

The following behaviour is not accepted:

- personal attacks, insults, harassment, intimidation, or threats;
- discriminatory or demeaning comments;
- repeated disruption of a technical or scientific discussion;
- deliberate misrepresentation of another participant's work or position;
- publication of private correspondence without permission;
- disclosure of credentials, tokens, private reviewer links, or security
  details;
- disclosure of restricted, controlled-access, identifiable, or potentially
  re-identifiable participant data;
- attempts to bypass source-data access requirements;
- retaliation against a person who raises a good-faith concern.

## Data and privacy

Public issues, discussions, and pull requests must not contain:

- identifiable participant information;
- controlled-access source data;
- private patient, sample, or institutional records;
- credentials or authentication material;
- private reviewer links;
- data whose redistribution is not permitted.

When evidence cannot be shared publicly, report the concern privately and
provide only the minimum information needed for investigation.

## Scope

This code of conduct applies to:

- repository issues, discussions, pull requests, and reviews;
- communication about contributions to this repository;
- public representation of the repository or its contributors;
- private communication when it directly concerns repository work.

It applies to maintainers, authors, contributors, reviewers, and other
participants.

## Reporting a concern

Routine scientific disagreement and reproducibility questions should be
raised through a GitHub issue with the relevant commit, package, file, and
evidence.

Report privacy, restricted-data, security, harassment, or other sensitive
concerns privately to:

`contact@helena.bio`

A report should include, where available:

- a description of the concern;
- the relevant repository location or communication channel;
- dates or approximate times;
- supporting records or links;
- any immediate privacy or security risk.

Do not include restricted data or credentials in the report unless a secure
exchange method has first been agreed.

## Review and enforcement

Maintainers will review reports in context and may request additional
information. Confidentiality will be preserved as far as reasonably
possible, while recognising that investigation may require limited
disclosure to affected parties.

Responses may include:

- clarification or mediation;
- correction or removal of content;
- a request to change communication behaviour;
- temporary restriction from participation;
- permanent restriction from the repository;
- escalation to the relevant platform, institution, data controller, or
  legal authority when required.

The response will be proportionate to the seriousness, persistence, and
consequences of the conduct.

## Good-faith scientific disagreement

A result is not protected from criticism because it is frozen, published, or
associated with the repository maintainers.

Good-faith disagreement is not misconduct. Raising a reproducible error,
questioning a model assumption, challenging an interpretation, or reporting
a failed reproduction is appropriate conduct when it is done accurately and
without personal abuse.

Likewise, disagreement does not justify overstating evidence, ignoring
documented claim boundaries, or presenting speculation as a verified
defect.

## Maintainer responsibility

Maintainers are expected to apply these standards consistently, disclose
relevant conflicts, distinguish scientific judgment from conduct
enforcement, and correct repository errors when evidence supports a
correction.
